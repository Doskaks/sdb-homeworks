### Задание 1

Опишите не менее семи таблиц, из которых состоит база данных:

- какие данные хранятся в этих таблицах;
- какой тип данных у столбцов в этих таблицах, если данные хранятся в PostgreSQL.

Приведите решение к следующему виду:

Сотрудники (

- идентификатор, первичный ключ, serial,
- фамилия varchar(50),
- ...
- идентификатор структурного подразделения, внешний ключ, integer).


### Решение 2
```
1. Таблица Сотрудники
`CREATE TABLE Сотрудники (
    сотрудник_id SERIAL PRIMARY KEY,
    фамилия VARCHAR(50) NOT NULL,
    имя VARCHAR(50) NOT NULL,
    отчество VARCHAR(50),
    оклад NUMERIC(10,2) NOT NULL CHECK (оклад >= 0),
    дата_найма DATE NOT NULL,
    должность_id INTEGER NOT NULL,
    подразделение_id INTEGER NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (должность_id) REFERENCES Должности(должность_id) ON DELETE RESTRICT,
    FOREIGN KEY (подразделение_id) REFERENCES Структурные_подразделения(подразделение_id) ON DELETE RESTRICT
);`

2. Должности
CREATE TABLE Должности (
    должность_id SERIAL PRIMARY KEY,
    название_должности VARCHAR(100) NOT NULL UNIQUE,
    уровень_грейда VARCHAR(20),
    описание TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

3. Типы подразделений
CREATE TABLE Типы_подразделений (
    тип_подразделения_id SERIAL PRIMARY KEY,
    название_типа VARCHAR(50) NOT NULL UNIQUE,
    код_типа VARCHAR(10) UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

4. Структурные подразделения
CREATE TABLE Структурные_подразделения (
    подразделение_id SERIAL PRIMARY KEY,
    название_подразделения VARCHAR(150) NOT NULL,
    тип_подразделения_id INTEGER NOT NULL,
    филиал_id INTEGER NOT NULL,
    руководитель_id INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (тип_подразделения_id) REFERENCES Типы_подразделений(тип_подразделения_id) ON DELETE RESTRICT,
    FOREIGN KEY (филиал_id) REFERENCES Филиалы(филиал_id) ON DELETE RESTRICT,
    FOREIGN KEY (руководитель_id) REFERENCES Сотрудники(сотрудник_id) ON DELETE SET NULL
);

5. Филиалы
CREATE TABLE Филиалы (
    филиал_id SERIAL PRIMARY KEY,
    адрес VARCHAR(255) NOT NULL,
    город VARCHAR(100) NOT NULL,
    регион VARCHAR(100) NOT NULL,
    индекс VARCHAR(20),
    телефон VARCHAR(20),
    email VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

6. Проекты
CREATE TABLE Проекты (
    проект_id SERIAL PRIMARY KEY,
    название_проекта VARCHAR(200) NOT NULL,
    описание TEXT,
    статус VARCHAR(20) DEFAULT 'активен',
    дата_начала DATE,
    дата_окончания DATE,
    бюджет NUMERIC(15,2),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

7. Назначения на проекты
CREATE TABLE Назначения_на_проекты (
    назначение_id SERIAL PRIMARY KEY,
    сотрудник_id INTEGER NOT NULL,
    проект_id INTEGER NOT NULL,
    дата_начала DATE NOT NULL,
    дата_окончания DATE,
    роль_в_проекте VARCHAR(50),
    занятость_процент INTEGER CHECK (занятость_процент >= 0 AND занятость_процент <= 100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (сотрудник_id) REFERENCES Сотрудники(сотрудник_id) ON DELETE CASCADE,
    FOREIGN KEY (проект_id) REFERENCES Проекты(проект_id) ON DELETE CASCADE,
    UNIQUE (сотрудник_id, проект_id, дата_начала)
);
```
Примечание:

    Нормализация данных: ФИО разделено на три отдельных поля для эффективной выборки и сортировки

    Денежные значения: Для оклада используется numeric(10,2) для точного хранения денежных сумм

    Внешние ключи: Все связи нормализованы через внешние ключи для целостности данных

    Адреса: Адрес филиала разделен на составляющие для гибкой фильтрации

    Проекты: Отдельная таблица назначений позволяет сотруднику работать на нескольких проектах одновременно

    Расширяемость: Таблица "Типы подразделений" позволяет добавлять новые типы без изменения структуры

    Индексы: Рекомендуется создать индексы по часто используемым полям (дата_найма, филиал_id и др.)
