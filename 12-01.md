### Задание 1

Опишите не менее семи таблиц, из которых состоит база данных:

- какие данные хранятся в этих таблицах;
- какой тип данных у столбцов в этих таблицах, если данные хранятся в PostgreSQL.

Приведите решение к следующему виду:

Сотрудники (

- идентификатор, первичный ключ, serial,
- фамилия varchar(50),
- ...
- идентификатор структурного подразделения, внешний ключ, integer).


### Решение 2

1. Сотрудники
сотрудник_id - первичный ключ, serial
фамилия - varchar(50)
имя - varchar(50)
отчество - varchar(50)
оклад - numeric(10,2)
дата_найма - date
должность_id - внешний ключ, integer
подразделение_id - внешний ключ, integer

2. Должности
должность_id - первичный ключ, serial
название_должности - varchar(100)
уровень_грeйда - varchar(20)

3. Типы подразделений
тип_подразделения_id - первичный ключ, serial
название_типа - varchar(50)

4. Структурные подразделения
подразделение_id - первичный ключ, serial
название_подразделения - varchar(150)
тип_подразделения_id - внешний ключ, integer
филиал_id - внешний ключ, integer

5. Филиалы
филиал_id - первичный ключ, serial
адрес - varchar(255)
город - varchar(100)
регион - varchar(100)

6. Проекты
проект_id - первичный ключ, serial
название_проекта - varchar(200)
описание - text

7. Назначения на проекты
назначение_id - первичный ключ, serial
сотрудник_id - внешний ключ, integer
проект_id - внешний ключ, integer
дата_начала - date
дата_окончания - date (nullable)

Примечания по проектированию:

    Нормализация данных: ФИО разделено на три отдельных поля для эффективной выборки и сортировки

    Денежные значения: Для оклада используется numeric(10,2) для точного хранения денежных сумм

    Внешние ключи: Все связи нормализованы через внешние ключи для целостности данных

    Адреса: Адрес филиала разделен на составляющие для гибкой фильтрации

    Проекты: Отдельная таблица назначений позволяет сотруднику работать на нескольких проектах одновременно

    Расширяемость: Таблица "Типы подразделений" позволяет добавлять новые типы без изменения структуры

    Индексы: Рекомендуется создать индексы по часто используемым полям (дата_найма, филиал_id и др.)
